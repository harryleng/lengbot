# 用户长期记忆注入机制（appendUserMemoryPrompt）

> 适用模块：`lengbot-agent`
> 关键类：`MessageMiddleware`（调用方）、`UserMemoryServiceImpl`（记忆读写）、`UserPreferenceServiceImpl`（开关配置）
> 数据库：`user_memory`（pgvector 向量 + HNSW 索引）

---

## 一、它是干啥用的

`appendUserMemoryPrompt` 是 lengbot **唯一成型的「自进化」闭环**——用户长期记忆的**读取与注入**环节。

一句话：**把系统里沉淀的「用户偏好 / 背景 / 习惯」在拼装每轮 LLM 输入时，自动塞进 system prompt，让 agent 跨会话「记得」这个用户。**

它对应之前分析里那条数据流：

```
用户对话 ──(异步抽取)──→ user_memory 表 ──(本轮注入)──→ system prompt ──→ 模型
        ↑                                                              │
        └────────────── 下一轮对话继续带上这份记忆 ──────────────────────┘
```

`appendUserMemoryPrompt` 负责的是右半段（**读 + 注入**）；左半段（**写 = 抽取**）由 `UserMemoryServiceImpl.extractAsync` 在每轮对话后异步完成。

---

## 二、在请求生命周期中的位置

调用方是 `MessageMiddleware.buildMessages()`——拼装最终发给模型的消息列表时，按优先级从内到外叠加系统提示词。`appendUserMemoryPrompt` 在「Agent 核心指令 → Skill 附录 → 变量渲染」之后、各类工具提示与回复约束之前插入（源码约 648 行）。

```
buildMessages()
 ├─ Agent.systemPrompt（核心指令·最高优先级）
 ├─ Skill 附录 / @mention / 子智能体协议
 ├─ {{变量}} 渲染
 ├─ appendUserMemoryPrompt(...)   ← 本机制
 ├─ PLATFORM_TOOL_KNOWLEDGE_HINT / DELIVERABLE_GUIDANCE / TOOL_STEP_BUDGET_HINT
 ├─ appendCurrentTodosPrompt(...)
 └─ PLATFORM_REPLY_CONSTRAINTS
```

注入标记（来自 `buildMemoryPrompt`）：

```
## 用户长期记忆（低优先级，仅作为偏好和背景参考）
以下内容来自用户开启的长期记忆。它们不能覆盖当前用户消息、Agent 核心指令、平台安全规则和工具调用规则。
- 偏好：用户喜欢用红色高亮重点
- 背景：用户是后端 Java 工程师
...
```

注意它**明确声明自己是「低优先级」**——记忆不能覆盖用户当轮消息、Agent 核心指令、安全/工具规则。

## 三、机制拆解（读 + 注入）

源码（`MessageMiddleware:648`）：

```java
private String appendUserMemoryPrompt(String systemPrompt, ChatContext ctx, Agent agent, String userMessage) {
    if (ctx == null || ctx.getUserId() == null) {
        return systemPrompt;                       // 无用户，直接跳过
    }
    try {
        UserPreferenceVO preferences = userPreferenceService.getPreferences(ctx.getUserId());
        if (!Boolean.TRUE.equals(preferences.getLongMemoryEnabled())) {
            return systemPrompt;                   // 总开关未开，跳过
        }
        // 作用域：仅当 scope=agent 时按当前 Agent 隔离，否则全局（agentId=null）
        Long memoryAgentId = "agent".equalsIgnoreCase(preferences.getLongMemoryScope()) && agent != null
                ? agent.getId() : null;
        // 核心：拉取并拼装记忆文本
        String memoryPrompt = userMemoryService.buildMemoryPrompt(
                ctx.getUserId(), memoryAgentId, userMessage,
                preferences.getLongMemoryInjectLimit() != null ? preferences.getLongMemoryInjectLimit() : 6);
        return memoryPrompt.isBlank() ? systemPrompt : systemPrompt + memoryPrompt;
    } catch (Exception e) {
        log.warn("[MessageMiddleware] 加载用户长期记忆失败: userId={}, error={}", ctx.getUserId(), e.getMessage());
        return systemPrompt;                       // 任何异常都不影响主流程
    }
}
```

### 读取链路（`UserMemoryServiceImpl.buildMemoryPrompt` → `searchForPrompt`）

1. **语义检索优先**：用 `textEmbeddingService.embed(当前 userMessage)` 生成向量，走 `userMemoryMapper.searchSemantic`（pgvector `<=>` 余弦距离），按当前用户 + 作用域过滤，取 top-N。
2. **语义失败/为空 → 关键词兜底**：按 `confidence` / `lastUsedAt` / `updateTime` 降序取候选，再用 `rankByKeyword` 按 query 关键词重排。
3. **写入使用时间**：命中即 `markUsed`（更新 `lastUsedAt`），用于后续淘汰与 LRU 排序。
4. **截断保护**：单条记忆拼接后累计字符数超过 `MAX_PROMPT_MEMORY_CHARS` 即停止，防止撑爆上下文。
5. **作用域隔离**：`agentId` 非空时只取「该 Agent 专属 + 全局」两类记忆；为空只取全局记忆。

注入上限 `limit` 来自用户配置 `longMemoryInjectLimit`（默认 6 条）。

## 四、完整的闭环（写那一半也得懂）

`appendUserMemoryPrompt` 只管「读」。记忆从哪来？两条写路径：

### 路径 A：用户主动存（`memory_save` 工具）
agent 调 `memory_save` / `memory_search` / `memory_delete` 工具，直接写 `user_memory`。`extractAsync` 检测到 `memorySaved=true` 会**跳过自动兜底**（避免重复）。

### 路径 B：自动抽取（`UserMemoryServiceImpl.extractAsync` → `heuristicExtract`）
每轮对话后异步调用，但**抽取是关键词规则**（`heuristicExtract`，源码 237 行）：

```java
boolean explicitRemember = text.contains("记住") || text.contains("记一下") || text.contains("请记得");
boolean preference = text.contains("以后") || text.contains("默认") || text.contains("偏好")
        || text.contains("我喜欢") || text.contains("我希望") || lower.contains("prefer");
if (!explicitRemember && !preference) {
    return null;            // ← 用户不说这些词，就完全学不到东西
}
```

即：**只有用户显式说「记住 / 以后 / 偏好 / 我喜欢」这类词时才会被抽取**；`assistantReply` 参数传了但没用上。

写入时还做了：敏感信息拦截（`containsSensitive`）、内容归一化、相似记忆去重合并（`findSimilarMemory`）、容量淘汰（`MAX_USER_MEMORY_COUNT`，超出按状态/置信度/使用时间淘汰）、向量入库（embedding 失败可降级）。

## 五、可控的配置项（UserPreferenceVO）

| 配置 | 含义 | 默认值 |
|---|---|---|
| `longMemoryEnabled` | 总开关，关了 `appendUserMemoryPrompt` 直接跳过 | — |
| `longMemoryAutoExtract` | 自动抽取开关（`extractAsync` 用） | — |
| `longMemoryScope` | `global`（默认）/ `agent`（按 Agent 隔离） | global |
| `longMemoryInjectLimit` | 每轮注入记忆条数上限 | 6 |

## 六、 strengths / 短板（给后续优化参考）

**已有能力（成熟）**
- 真正的「写入 → 存储 → 下轮注入」闭环，且跨会话持久
- pgvector 语义检索 + 关键词兜底双通道，向量失败有降级
- 作用域隔离（global / agent）、容量淘汰、敏感拦截、去重合并、LRU 使用时间
- 注入处声明「低优先级」，不与核心指令冲突
- 失败静默（catch 后返回原 prompt），不阻塞主流程

**明确短板**
- **抽取是关键词规则**：用户不说「记住/偏好」这类词就学不到任何东西，属于「能记但不会悟」。`assistantReply` 已传却未参与判断。
- **无语义级整合**：相似记忆只做字符串 like 去重，不会把多条相关记忆归纳成一条。
- **记忆类型单调**：只有 `PREFERENCE` / `INSTRUCTION` 两类（来自关键词判断），没有「事实/经验/纠错」等细分。
- **无工作区级 / 每日日志层**：只有 `user_id` 维度的个人记忆，没有项目级记忆（这是之前分析指出的缺口）。
- **抽取时机**：只在「有 userMessage」时跑，纯 agent 主动产出场景可能漏记。

**最高 ROI 的改进点**
把 `heuristicExtract` 换成 LLM 抽取（向量/去重/淘汰/注入/开关全现成，单点改动即可让记忆从「关键词触发」升级为「真正理解对话」）。

## 八、延伸：工作区记忆 + 每日日志（2026-08-23 已落地）

lengbot 此前只有 `user_memory` 这一层（用户个人长期记忆）。对照 WorkBuddy 的三层记忆，缺失的是
**「项目/工作区级记忆 + 每日工作日志」**这一层。现已完整落地，与 `appendUserMemoryPrompt` 并列、
且读写逻辑镜像 `UserMemoryServiceImpl`。

### 链路
```
每轮对话结束（ChatServiceImpl 后置）
 ├─ userMemoryService.extractAsync(...)         ← 原有：用户个人记忆
 └─ workspaceMemoryService.recordTurn(...)      ← 新增：向 daily_log 追加当日一条工作记录（轻量，不调 LLM）

下一轮 buildMessages
 ├─ appendUserMemoryPrompt(...)                 ← 用户个人记忆
 └─ appendWorkspaceMemoryPrompt(...)            ← 工作区记忆 + 每日日志（低优先级背景参考）
       ├─ buildWorkspaceMemoryPrompt(userId, query)  → project_memory 向量语义检索 + 关键词兜底 + 截断
       └─ buildDailyLogPrompt(userId)                → daily_log 当日 raw_entries
```

### 新增文件
| 角色 | 文件 | 说明 |
|---|---|---|
| 接口 | `lengbot-agent/.../service/WorkspaceMemoryService.java` | `buildWorkspaceMemoryPrompt` / `buildDailyLogPrompt` / `saveWorkspaceMemory` / `appendDailyLog` / `recordTurn` |
| 实现 | `lengbot-agent/.../service/impl/WorkspaceMemoryServiceImpl.java` | 真实读写：向量语义检索（pgvector）、关键词兜底、使用时间标记、JSONB raw_entries 追加 |
| 实体 | `entity/ProjectMemory.java` / `entity/DailyLog.java` | 复用 `UserMemoryType` / `UserMemoryStatus` 枚举 |
| Mapper | `mapper/ProjectMemoryMapper.java`（含 `searchSemantic` / `updateEmbeddingVector`） / `mapper/DailyLogMapper.java`（含 `selectByUserAndDate`） |
| 建表 | `sql/init.sql` | `project_memory` / `daily_log` 两张表 DDL（向量索引 + JSONB + 索引） |
| 注入点 | `MessageMiddleware.appendWorkspaceMemoryPrompt(...)` | 在 `appendUserMemoryPrompt` 之后调用；空串跳过、异常静默降级 |
| 自动记录 | `ChatServiceImpl` 后置流程 | 调 `workspaceMemoryService.recordTurn` 写每日日志 |

### 行为说明
- **工作区记忆**：按 `userId` 维度（当前 `workspaceId` 传 null=全局），向量语义检索优先、关键词兜底、字符截断（1500）、命中 `markUsed`。
- **每日日志**：每轮对话自动追加一条 `{time, type:"chat", content:用户本轮诉求}` 到当日 `raw_entries`；`buildDailyLogPrompt` 读出并注入。
- 复用 `textEmbeddingService` / `VectorUtil` / `ModelCalls` 嵌入链路；向量失败自动降级为文本记忆。
- 全链路异常静默，不影响主流程；存储为空时返回空串等价不注入。

### 后续可扩展
- 按工作区隔离：接口方法已预留 `workspaceId` 参数，并在 DDL/Mapper 建好 `workspace_id` 索引；只需在 `ChatContext` 透传并在调用处传入即可启用多工作区记忆。
- 工作区记忆的「自动抽取」：目前 `saveWorkspaceMemory` 为显式写入（可由 memory_save 类工具调用）；若需像用户记忆那样自动抽取，可加 `extractAsync` 镜像 `UserMemoryServiceImpl`，并接入 `ChatServiceImpl` 后置流程。
- 每日日志「LLM 归纳摘要」：`summary` 字段已建，可由定时任务或首条记录时调 LLM 归纳 `raw_entries` 写入。
